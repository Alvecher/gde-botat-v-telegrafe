# Где ботать в Телеграфе

Интерактивная карта кампуса «Центральный телеграф» (ЦТ): карта, под ней дата и слайдер времени, аудитории подсвечены по занятости. Публикуется на GitHub Pages и обновляется сама каждый день.

## Как пользоваться (сайт)

Ничего делать не нужно: сайт обновляется сам каждый день в 10:00 по расписанию GitHub Actions (`.github/workflows/update.yml`) и публикуется на GitHub Pages.

Два варианта, оба открываются по ссылке репозитория на Pages:
- `site/index.html` (главная): всё на одном экране. План 3 этажа, в правом нижнем углу врезка «2 этаж» с E201, S202.1, S202.2, S203 и плашкой «Столовая: можно ботать».
- `site/floors.html`: этажи по отдельности с переключателем, на 2 этаже столовая обведена целиком.

Между версиями есть ссылка-переключатель в шапке каждой страницы.

## Как это обновляется

`auto_update.py` раз в день скачивает выгрузку с cu-schedule.ru по тому же адресу, что и кнопка «Скачать Excel → Списком → Всё расписание» на сайте, проверяет её и только при успехе пересобирает обе страницы:

1. Скачивает файл, при сетевой ошибке повторяет попытку до 3 раз.
2. Проверяет: это действительно xlsx, строк не подозрительно мало (не пустая выгрузка вроде той, что была утром 23.09.2026, когда cu-schedule получал 401 от LMS), есть хотя бы одно занятие в аудиториях карты, а число строк не упало резче чем в 2 раза от прошлой удачной выгрузки.
3. **Если любая проверка не прошла — сайт не трогается**, остаётся прежним. Причина пишется в лог запуска (вкладка Actions в репозитории).
4. Если всё в порядке — пересобирает `site/index.html` и `site/floors.html` (запись атомарная, через временный файл, так что сайт никогда не окажется наполовину собранным) и коммитит `data/last-good.json` — это только числа (сколько строк и занятий было), без имён.

Локально (без GitHub) то же самое: `python3 auto_update.py`. Ручная пересборка из своего файла: `./Обновить\ карту.command путь/к/файлу.xlsx` или `python3 build_site.py путь/к/файлу.xlsx` (нужен только `openpyxl`).

## Хостинг: GitHub Pages

Настройка (один раз):

1. Создать **публичный** репозиторий на GitHub и запушить в него содержимое этой папки (кроме `data/raw`, `data/occupancy.json`, `data/last-good.xlsx` и собранных `site/index.html`/`site/floors.html` — всё это в `.gitignore`, генерируется заново).
2. В репозитории: **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. Готово. Workflow сразу собирает сайт по расписанию (10:00 МСК = 07:00 UTC) или вручную по кнопке **Actions → Обновить карту и опубликовать → Run workflow**.

Никаких платных подписок и секретов настраивать не нужно: используется только встроенный `GITHUB_TOKEN`. Публичный репозиторий — обязательное условие бесплатного Pages для личного аккаунта.

**Что окажется в открытом доступе:** код сборки, геометрия карты, названия курсов/типов занятий/время из расписания (это и так публично на cu-schedule.ru). Имён преподавателей на страницах нет, `data/` с сырыми выгрузками в git не попадает.

## Что на карте

| Цвет | Значение |
|---|---|
| Красный | занята в выбранный момент |
| Жёлто-зелёный | свободна сейчас, но в этот день ещё будет пара |
| Зелёный | свободна сейчас и до конца дня |
| Голубой | столовая (обеденный зал, 2 этаж): можно заниматься |
| Серая штриховка | недоступно студентам: офисы, учебный офис, техно точка, кухня для сотрудников, зоны «Work in progress» |

Кухни, туалеты, кафе, коворкинги, атриум остаются как на исходном плане. Неподписанные помещения на плане (подсобки, небольшие комнаты без названия) не раскрашиваются.

На плане вместо плашек «Аудитория» крупные номера. При наведении (на телефоне: тап) снизу выезжает подсказка со статусом аудитории, 9 слотами пар дня (свободно или занято) и списком занятий.

Масштаб: схема приближается сама внутри рамки (щипок двумя пальцами, до 5 раз; после приближения один палец двигает схему; кнопки «+», «−», «⤢»; на ноутбуке щипок на тачпаде). Браузерный зум страницы выключен, поэтому подсказка снизу на телефоне всегда обычного размера. Если комната при тапе оказалась бы под ней, страница подкручивается.

Перемены: если пара только что закончилась и следующая начнётся в пределах 15 минут (обычная перемена 10 минут, вечером 15), аудитория на перемене красная, в подсказке «перемена, в 11:30: …». Если после пары ничего нет, она сразу зелёная или жёлто-зелёная. Если перед парой аудитория пустовала, за 5 минут до начала она ещё жёлто-зелёная: это не перемена. «Занята до» считает пары подряд как одну занятость.

Ограничения данных:
- учитываются только занятия из расписания; брони под мероприятия и встречи туда не попадают;
- время московское;
- если выбранная дата вне периода таблицы, страница честно пишет «нет данных», а не красит всё зелёным.

## Как устроено

**Принцип:** свободные = все аудитории карты минус занятые в момент t.

- **Аудитории.** Только S, N, W, E на 2 и 3 этаже ЦТ: 28 штук (2 этаж: E201, S202.1, S202.2, S203; 3 этаж: E301, E303, N318-N324, W316, W317, S304-S315 включая S306.1 и S306.2). Все 28 встречаются в расписании осени 2026.
- **Таблица.** Листы по неделям, колонки ищутся по заголовкам (`Дата`, `Начало`, `Конец`, `Аудитория`, `Название`, `Тип`), поэтому перестановка колонок не ломает сборку. Составные аудитории (`N322 + N323`) разбиваются, `S202-1` приводится к `S202.1`. Если в таблице появится аудитория S/N/W/E, которой нет на карте, сборка напишет предупреждение.
- **Карта.** `map/extract_rooms.py` один раз восстановил контуры помещений из векторного PDF-плана: рендер только стен, морфологическое закрытие дверных проёмов, заливка от плашки с подписью, контур в многоугольник, точка для номера в самом широком месте комнаты. Для четырёх мест, где проёмы слишком широкие, в скрипте прописаны виртуальные стены (`CUTS`). Результат: `map/rooms.json`, подложки `map/floor{2,3}.svg` (плашки аудиторий, недоступных зон и столовой закрашены цветом пола, копия PDF правится только в памяти) и отдельный слой стен `map/walls{2,3}.svg`. Перезапускать нужно только при новом плане, зависимости в отдельном venv: `pymupdf opencv-python-headless numpy`.
- **Слои страницы:** подложка → сплошная заливка комнат → стены поверх (поэтому края заливки ровные) → номера.

Проверка на данных 23.09.2026: статусы всех 28 аудиторий в 11:25, 12:55 и 14:25 (моменты перемен) совпали с независимым расчётом по сырой таблице, 84 сравнения, 0 расхождений.

## Файлы

- `build_site.py`: сборка обеих версий страницы из xlsx (функция `build()`, переиспользуется из `auto_update.py`).
- `auto_update.py`: ежедневное скачивание выгрузки и проверка перед пересборкой.
- `.github/workflows/update.yml`: расписание, сборка, публикация на Pages.
- `Обновить карту.command`: ручная сборка из своего файла и открытие.
- `site/template.html`: общий шаблон обеих версий (стили, логика), режим задаётся `layout` в данных. `site/index.html` и `site/floors.html` генерируются и в git не хранятся.
- `map/`: геометрия помещений и подложки этажей, скрипт их извлечения.
- `scraper/fetch_schedule.py`, `Собрать расписание.command`: ранняя попытка брать расписание по API (см. ниже), для текущей версии не нужны.

## Почему не API

Проверено 23.09.2026:
- **cu-schedule.ru** отдаёт JSON (`/api/timetable`), утром его бэкенд получал 401 от LMS по всем дням и возвращал 0 событий. К обеду сайт восстановился, Excel-выгрузку с него и используем. Зависимость от чужого прототипа остаётся, поэтому `auto_update.py` не публикует сайт при пустом или подозрительном ответе.
- **LMS напрямую** (`my.centraluniversity.ru/api/micro-lms`): эндпоинт «все занятия за дату» `calendar-events/single-date` для студенческой cookie отвечает 403, в том числе с параметром `courseIds`. Судя по коду фронтенда, это инструмент преподавателей для отметки посещаемости. Студенту работает `calendar-events/learn/courses/{courseId}/events/{YYYY-MM-DD}`, проверено на своих курсах (список: `v0/attendance/learn/courses`), в ответе аудитория лежит в `locationTitle`. Чужие курсы не проверялись, а каталог курсов студенту показывает только свои, так что полный список курсов здания из LMS не получить.
- `scraper/fetch_schedule.py` написан под `single-date` и поэтому для студента не работает; оставлен как задел, если появится доступ с правами сотрудника.
